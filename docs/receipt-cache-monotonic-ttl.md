# 回执缓存 TTL 与时钟回拨

## 问题

`ReceiptMemoryCache` 原来用 `Date.now()` 同时计算 `expiresAt`、执行 `set()` 的过期清理、以及 `get()` 的到期判定。挂钟不是单调的：NTP step、虚拟机迁移、容器时钟重置都可能让它回拨。

复现（过期后没有任何 `get()`/`has()` 触发惰性删除）：

```ts
let t = 1_000;
Date.now = () => t;
const cache = new ReceiptMemoryCache(100, 10);
cache.set("r", { receiptId: "r", payer: "p", amount: 1n, timestamp: 0 }); // expiresAt = 1100
// 需要一个长 TTL 条目让缓存"观测"到 1200：直接把时钟前跳而不调用缓存，
// 新实现也无法知道峰值曾经存在（见下方边界一节）。
cache.set(
  "observer",
  { receiptId: "observer", payer: "p", amount: 1n, timestamp: 0 },
  1_000_000,
);
t = 1_200;
cache.get("observer"); // TTL 已过，且没有调用 set() 触发清扫
t = 1_050; // 时钟回拨到到期时刻之前
cache.has("r"); // 旧实现：true；回执"复活"
```

影响是一个已经超过 TTL 的回执重新被当作缓存命中。该类本身不是持久化防重放，但缓存命中语义错误仍会让调用方得到与配置 TTL 不一致的结论；`set()` 的清理同样失效，陈旧条目会占用容量并挤掉活跃条目。

## 方案

1. 默认时间源改为 `performance.now()`（进程单调时钟），与挂钟解耦。
2. 新增可选第三构造参数 `clock: () => number`，供测试确定性注入；前两个参数的含义和默认值不变。
3. `monotonicNow()` 每次读取时钟后，把实例的 `lastObservedMs` 钳制到"迄今观测到的最大值"。即使注入的时钟回拨，本实例已观测到的时间点也不会倒退。
4. `set()` 的清理、`get()` 的到期判定、新条目的 `expiresAt` 全部使用这同一个单调值；`CachedReceipt.timestamp` 是调用方提供的业务字段，保持原样。
5. 非法时钟（非函数、返回 `NaN` / `Infinity` / 负数）明确抛 `Invalid monotonic clock`，不静默降级成挂钟。

构造校验从原来的"TTL / 容量"扩展到"时钟必须是函数"，错误信息仍是 `Invalid cache limits`。

## 边界

- 钳制只能记住**缓存实际观测过**的时间峰值。若注入时钟先向前跳再回拨，但期间没有任何缓存调用，实例无从得知峰值——默认 `performance.now()` 不存在这种情况，因为它本身不会回拨。注入时钟的调用方需要自己保证这一点。
- 进程重启后单调时钟从零重新开始，缓存本身也在内存中一并消失，因此不会跨进程续期。
- 本改动不提供持久化防重放，也不校验回执是否真的结算过；这些仍由 `ReceiptStore` / facilitator 负责。

## 与开放 PR #142 的关系

#142 修的是同一个文件的**输入快照**问题（getter 在校验与存储之间换值），本改动修的是**时钟语义**，二者独立。如果维护者要求，可以在任一方向上 rebase：#142 移到快照后，本改动的 `set()` 只需把 `const now = this.monotonicNow()` 保留在校验之前，不会与快照逻辑冲突。

## 验证

- 新增 `tests/receipt-cache-monotonic-ttl.test.ts`：11 个用例，覆盖过期未读后回拨不复活、正常到期、反复振荡、陈旧条目清理、同键重设、挂钟变化无效、业务字段保持、返回值隔离、非法时钟与构造校验。
- 非假绿（同一套 11 个测试跑了三个版本）：精确旧实现（上游 `b910552` 原文件）**8 fail / 3 pass**；保留注入时钟但**仅去掉钳制**的版本 **4 fail / 7 pass**；完整修复 **11 pass**。第二组结果证明测试确实覆盖钳制这个修复点，而不是只覆盖"换了时间源"。
- 独立复审曾指出头条用例最初把回拨目标设成 1050、而 `expiresAt` 只有 100，不修也会过；已改为 1000 起跳、1100 到期、经长 TTL 条目观测 1200 后再回拨 1050。
- 既有边界测试 `tests/pr-63-64.test.ts` 原本通过改写全局 `Date.now` 注入时间，现改为使用新的时钟注入参数，断言语义（精确到期边界）不变。
- `npm run check` 全绿：67 文件 / 455 用例通过，typecheck 与 build 通过。
